# 5.5.89 — Restore IA catalog breadth at the database handoff

## Reproduced cause

The strict IA engine was reading the newest 96 D1 rows before file qualification.
Older healthy programs disappeared behind incomplete new rows, and deeper relay
unions were truncated again during session selection and background persistence.
An episode-count gate alone did not prove a broad selection of different shows.

## Bounded repair

- Repaired IA requests can pass up to 512 qualified candidates through the API,
  session catalog and durable import; the public shelf remains one playing plus
  two ready items (or the existing caller-requested maximum of five).
- D1 prefers recent transport qualification, balances show families, and uses
  unseen/oldest-served history. Incomplete siblings do not consume qualified
  episodes' family positions.
- Legacy explicit media URLs in metadata are eligible for the existing strict
  qualification gate when the normalized URL column is empty. This does not
  infer a URL or turn missing metadata into verification.
- If editorial rejection shrinks a window, up to four bounded D1 pages are read
  through the unchanged qualification gate. No Archive discovery is performed
  by that refill. Scan counts/truncation are reported rather than claiming an
  unlimited foreground catalog.
- Catalog imports preserve their tail and use at most 32 statements per D1 batch.
  Repaired imports split into UTF-8 byte-bounded queue messages below 120,000 bytes.
- Existing background discovery from 5.5.88 remains active. No channels are hidden,
  removed or newly enrolled; desktop 10/150 remain the production pilot.
- OK, Vimeo, Source Suite and FAST admission/rotation behavior is not changed.

## Verification before release

Nine new behavioral regressions cover crowded-out older records, 140-item session
and relay unions, legacy metadata URLs, durable tail persistence, dominant-series
crowding, incomplete sibling ranks, strict rejection refill, and queue bytes.
The affected qualification/discovery/review suite passes 65 tests. All 49 local
Node commands extracted from hosted CI pass on the final code.

Live loopback evidence: six serial rotations per station, 18 distinct episode
selections per station, three qualified items every rotation, no repeats/resets.
Cartoon queue requests: 233–9,161 ms, including a cold first request; TV: 33–1,007
ms. These are queue timings, not decoded-frame latency. The loopback harness has
no production D1 binding; actual SQLite regressions verify the D1 query itself.

The Node loopback preflight was inaccessible in this environment. The Windows
HTTP client and in-app browser reached the same server; its complete rotation
evidence is retained in artifacts/5.5.89-windows-rotations.json. Failed preflights
are retained, not counted as channel failures or silently discarded.

## Not claimed complete

This repair prevents catalog loss at the existing handoff. It does not prove every
old unqualified record has been rehydrated, thousands of playable episodes per
station, all-169 IA certification, physical mobile/Cast certification, or subsecond
cold playback. Pending metadata/backfill and exact guide-to-recovery identity remain
separate work. Wider enrollment must follow measured genre/playback evidence.

Rollback: revert this release commit and redeploy the prior API/client release.
Catalog changes are additive; no migration or deletion is required.
