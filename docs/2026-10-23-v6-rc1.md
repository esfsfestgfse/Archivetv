# RealSignal 6.0.0-rc.1 — Retro Cable

## What this release means

This is the first explicitly numbered **Version 6 release candidate**, following
the user's request to advance V6 on October 23. It is not final 6.0.0 certification.
The new shell and full guide still require `v6=1`. Default and connected-Cast
presentation remain with their existing owner. No playback engine, catalog,
channel number, source adapter, saved history or provider configuration changed.

- Desktop: `https://esfsfestgfse.github.io/Archivetv/the_dial_desktop.html?v6=1&build=6.0.0-rc.1`
- Mobile: `https://esfsfestgfse.github.io/Archivetv/the_dial_mobile.html?v6=1&build=6.0.0-rc.1`

The tab titles, diagnostic stamps, compact version chips, shell label and asset
cache versions all identify the RC. Removing `v6=1` selects the prior UI. The
previous production commit is `96427d61667cbe0fa517fceadddf57ddee1d7011` for code
rollback; no storage migration or history deletion is needed.

## Changes since 5.6.32

1. Guide refresh measures all row bounds before writing titles. Previously it
   alternated geometry reads with text changes, inviting repeated forced layouts.
   The visible selected row and detail panel now share one snapshot per refresh.
2. Compact/reflowed windows keep both a browsable channel list and Watch inside
   the viewport. At 640x360 the prior Watch bottom was 453.94px, beyond the screen;
   the repaired layout places it at 345px. Detail text scrolls independently.
3. Guide-only CSS/JS edits now trigger GitHub CI.
4. Existing release validators admit V6 stable/numbered-RC stamps while continuing
   to reject stale or malformed versions. The compact chips retain `-rc.1` rather
   than falsely displaying final `v6.0.0`.

Guide browsing remains read-only and does not fetch catalogs, warm queues, tune,
or advance watch history. Unknown current/next data stays pending/unavailable.

formatter tests reproduced the missing prerelease suffix before correction.

## Remaining before final V6

- Finish cold guide/paint timing and actual enlarged-text/device checks. The
  above samples are not an all-device or all-channel latency guarantee.
- Implement and verify the approved fail-open inter-program commercial scheduler
  and independent, balanced ad history; no ad-scheduling changes shipped here.
- Full cross-family release regression, canary/rollback check and user review.
  Physical Cast behavior is unchanged, not newly certified by browser mocks.
- Existing long/recursive upstream episode labels remain a metadata issue. This
  guide does not invent replacement titles or claim all untuned queues are full.

## Decision made

Use `6.0.0-rc.1` instead of another 5.6.x preview in response to the user's V6
request. This changes the preview naming only, not the release gates or default
rollout boundary. Cost: fallback users also see an RC diagnostic build string;
the links and labels explicitly distinguish it from the final release.
