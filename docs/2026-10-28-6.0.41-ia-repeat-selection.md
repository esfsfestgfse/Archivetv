# RealSignal 6.0.41: bounded IA repeat-selection repair

## Changed

The standard desktop/mobile IA client previously treated an empty filtered
five-item response as freshness exhaustion. An overlapping or stale response
could therefore reactivate a skipped program even when `candidateItems` in
that same response contained an unseen, resolved episode.

Before relaxing freshness, the client now checks that existing deeper catalog.
It admits only records with a media URL that pass the existing channel rules
and local viewing/skip checks, removes duplicate IDs, and takes at most the
requested shelf size. No extra discovery request or metadata hydration is
added. Genuine ready-catalog exhaustion retains the existing recovery path.

The guarded reservation channels (10, 12, 22, 150) keep their separate owner.
Channel numbers, catalogs, stored history, guide ownership and the API are
unchanged. The client stamp is 6.0.41; the unchanged API remains
6.0.40-comedy-startup-language.

## Evidence

- The new behavioral regression failed before the repair: `already-skipped`
  was selected instead of the available `unseen-episode`.
- After repair both clients select the unseen episode. Tests also reject
  metadata-only/off-genre candidates and duplicates, and preserve exhausted
  catalog recovery.
- 99 affected tests passed, followed by all 94 release-check commands.
- One bounded review found no important issues.
- The local stamped desktop build decoded Aviation's Thunderbirds at 720x480
  and, after Next, a different Vulcan program at 640x480. Playback clocks
  advanced; compositor first-frame measurements were 5,184ms and 3,120ms.
  This is a playback smoke check, not evidence of faster startup or a browser
  reproduction of the controlled stale-response fixture.

## Findings that must not be confused with fixes

The existing nightly report's 60.3% freshness measures overlap between direct
relay shelves, bypassing the viewer-session API. It cannot by itself establish
the same percentage of viewer repeats. No thresholds or workflow gates were
changed to make this release look cleaner.

A bounded API comparison returned 18 different head IDs in 18 selections on
three channels. That measures selection, not decoded playback, and does not
certify the guarded channel's reservation path.

Actual Hard Count playback caught a separate content-identity repeat:
`dvd-transfer-224::Super Bowl X (2023 NFL Network Rebroadcast).ia.mp4` and
`dvd-transfer-224::Title 1 - Super Bowl X (2023 NFL Network Rebroadcast).ia.mp4`.
Archive metadata reports identical SHA-1
`953f9770cf346f8ec0e9a16894278de93550a208`, byte count 1,017,282,341 and runtime
10,803.29 seconds. Different IDs are not proof of different programs.
That duplicate-file identity issue remains open. Hard Count also attempted
news recordings and needed up to 9,160ms to recover through failed files.
No claim of genre or latency repair is made here.

## Next bounded repair

Use verified file identity/original relationships to prevent the same program
under different filenames from consuming separate rotation slots. Preserve
distinct episodes and continuation parts. Reproduce the hash-confirmed example
first; do not replace this with another all-channel audit.

No full IA soak or physical phone/Cast certification was repeated for this patch.
Version 7 remains unclaimed.
