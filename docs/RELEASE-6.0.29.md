# RealSignal 6.0.29 — Source depth and PeerTube playlist playback

Documentary Desk could repeatedly spend 15 seconds trying an HLS component as a standalone MP4. PeerTube metadata also offered an audio-only progressive alternative. The adapter now selects a complete video rendition: progressive video when available, otherwise the provider-declared HLS playlist. Existing fragmented-file cache entries resolve the same program through its same-origin public metadata; IDs and history stay intact. No playlist filename is guessed.

A real Chrome check exposed a second problem: native HLS returned `maybe` but rejected the actual AVC/AAC playlist. The shared player prefers supported Hls.js and retains native HLS for browsers without MediaSource support. Tune aborts and media teardown destroy owned loaders. Pre-start failures try another candidate; post-start fatal errors reject/advance the failed program instead of leaving a dead player. Independent review found both lifecycle gaps, and new executable regressions cover them.

Black Stage, Classroom, Comfort Television and Foodways gain named-program discovery rails and retain the normalized long-form search contract. Previously `normalizedProfile` discarded `longForm`, allowing search into the mostly sub-15-minute medium bucket. The 15-minute admission floor, landscape requirement and AI/podcast/fan/parody exclusions remain. Black Stage stays a Black stage/performance channel. Comfort Television stays quiet crafts/home/garden programming. An actual ancient-astronaut documentary admitted through an actor's Home Improvement credit is now rejected using title/creator topic evidence. English programs about Spanish cooking no longer fail language detection merely for that subject phrase; explicit non-English declarations and dub labels remain rejected.

Local full-app Documentary Desk results: previously failed PeerTube items produced compositor-confirmed pictures in 2.834, 2.985 and 2.162 seconds, one attempt each, no early repeat. A following YouTube program reported an advancing player clock after 607 ms; that is recorded separately, not called a compositor-confirmed frame. An isolated decode of the first previously failed program showed 854×480 video in 682 ms and continued beyond 27 seconds. Opt-in local diagnostics now separate catalog publication, native selection and embed-clock startup. They send no diagnostic network requests.

Existing catalogs, viewing history, IA and OK/Vimeo behavior, numbers and lineup remain. No migration or history reset is required. Bounded profile refresh and hosted status results will be reported separately. This release is a Version 7 repair milestone, not Version 7 certification; Chrome mobile layout tests cannot certify a physical phone or Cast receiver.
