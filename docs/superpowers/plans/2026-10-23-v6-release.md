# RealSignal 6.0.0 release implementation plan

> Native implementation with one final independent review. The user explicitly
> requests the full release and rollout on 2026-10-23; do not stop at another RC.

**Goal:** Finish safe commercial handling, promote the approved UI to default,
verify the release, publish 6.0.0 and give an evidence-based development roadmap.

**Architecture:** Retain all providers, catalogs and playback owners. Add a small
shared commercial policy over the existing ad engine; promote the presentation
adapter with `v6=0` as an explicit rollback. No backend service/schema migration.

**Stack:** Existing plain JS/CSS/HTML, Node/Python CI and browser checks.
**Spec:** `docs/superpowers/specs/2026-10-21-realsignal-v6-retro-cable-design.md`

## Constraints and release decisions

- No lineup, channel-number, catalog, freshness or source-provider changes.
- No time-of-day restrictions, viewer rate limits, new data channels or builders.
- Keep Cast discovery/protocol/receiver presentation, Roku and Vimeo unchanged.
- User now authorizes default rollout and final naming; retain honest reporting
  of physical-device and latency limitations. A release is not a claim that every
  upstream provider or physical receiver has newly passed certification.
- Ads remain inter-program, video on TV/audio on audio channels; never stack
  over source-owned live advertising. A cold ad is skipped, never searched at EOF.
- One ad per break, at most 60 seconds; short cartoons accrue 25 minutes before
  an eligible break. Preserve existing holiday two/three-program cadence.

## Review focus

1. An ended show's return cache must be cleared before an ad/bumper can return.
2. An unavailable ad must not trigger discovery or delay the next program.
3. A stale ad result/timer after Next, channel change or power-off cannot affect
   a new tune; retry warming must not outlive its channel.
4. Default UI and explicit rollback must each have one guide owner, including
   connected-Cast transitions and native keyboard activation.
5. Tests must actually exercise default UI rather than hidden legacy controls;
   no test can be weakened to ignore wrong media, broken controls or stale stamps.
